# mlsd-judge

**Автоматическая проверка студенческих работ LLM-агентом: оценка качества
и цикл улучшения.** Проект курса ML System Design.

## Зачем

На проектных курсах студенты сдают работы pull request'ом, а преподаватель
принимает их по критериям курса. Сверка каждого критерия с репозиторием —
большая часть времени приёмки.

Судья — LLM-агент, который до приёмки читает сдачу в песочнице и по
каждому критерию выносит вердикт «закрыт / не закрыт» с опорой: где в
работе это видно. Преподаватель получает готовые вердикты и вопросы на
приёмку и тратит время только на спорное. Судья уже проверяет сдачи живых
потоков курса с осени 2026.

Ошибка агента дорого стоит:

- **ложное «закрыто»** — пропущенный недочёт, который не всплывёт на
  приёмке;
- **ложное «не закрыто»** — лишний вопрос и недоверие студентов к агенту.

Проект — про то, как мерить качество судьи и улучшать его так, чтобы
каждая новая версия была измеримо не хуже прежней.

## Что делаем

```mermaid
flowchart LR
    S[Сдача: PR и критерии] --> J[Судья: разведка в песочнице и суждение]
    J --> V[Вердикты с опорами]
    V --> H[Приёмка человеком]
    H --> E[Эталон: разметка вердиктов людьми]
    E --> Ev[Эвал: метрики на эталоне и мутациях]
    Ev -->|новая версия не хуже| J
```

- **Модель** — конфигурация судьи: LLM, подсказки разведки и суждения,
  инструменты, бюджет шагов.
- **Бейзлайны** — текущая версия судьи и простой вариант: один вызов LLM
  на критерий без разведки.
- **Данные** — эталон из размеченных людьми вердиктов, мутации сдач с
  известным ответом (удалить артефакт, переименовать, добавить шум,
  вставить инъекцию) и повторы одной сдачи.
- **Улучшение** — итерации подсказок по провалам эвала; замена версии —
  только если она проходит гейт на отложенной части набора.

## Метрики

| Метрика | Как считаем | Ориентир |
|---|---|---|
| Ложное «закрыто» | доля «закрыт» там, где эталон «не закрыт» | главная, ↓ |
| Согласие с людьми | κ Коэна, точность и полнота по типам критериев | κ ≥ 0,7 |
| Чувствительность R | поломка сдачи → «не закрыт» | ≥ 90% |
| Инвариантность S | переименование, шум, перефразирование → вердикт не меняется | ≥ 95% |
| Инъекции | вердикты не изменились / вставка найдена | 100% / ≥ 90% |
| Повторяемость | перевёрнутые вердикты на трёх прогонах | ≤ 5% |
| Цена и время | токены и минуты на сдачу | не хуже текущей версии |

Бизнес-метрики — пропуск недочётов на приёмке по критериям, закрытым
судьёй, и минуты приёмки на работу. Обе считаются из данных платформы.

Подробно — в дизайн-документе `docs/ml_system_design_doc.md` (ДЗ 1).

## Данные и приватность

Авторы сдач согласились на использование их работ для эвала. Сами сдачи
в репозиторий не попадают: здесь только обезличенные выгрузки (ID вместо
людей, команд и репозиториев) и агрегаты. `data/raw/` в `.gitignore`.

## Структура

    src/judge/       код судьи
    docs/            дизайн-документ и материалы по этапам
    pyproject.toml   зависимости и настройки ruff и ty

## Как начать

Нужен [uv](https://docs.astral.sh/uv/) — он сам поставит Python 3.13.

```bash
uv sync
uv run pre-commit install
```

Проверки:

```bash
uv run ruff check .          # линтер
uv run ruff format .         # форматер
uv run ty check              # типы
uv run pre-commit run --all-files
```

## pre-commit

На каждый коммит запускаются:

- гигиена файлов: пробелы в конце строк, перевод строки в конце файла,
  валидность YAML и TOML, конфликты слияния, крупные файлы;
- поиск секретов — `gitleaks` и `detect-private-key`;
- `uv lock --check` — `uv.lock` совпадает с `pyproject.toml`;
- `ruff check --fix` и `ruff format`;
- `ty check` — проверка типов;
- проверка сообщения коммита на Conventional Commits.

## Коммиты

[Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/):
`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `perf:`, `build:`, `ci:`,
`chore:`. Описание — по-русски, без точки в конце.
